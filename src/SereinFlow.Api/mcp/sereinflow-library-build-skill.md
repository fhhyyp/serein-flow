# SereinFlow Library Build and ZIP Packaging

Build the library locally with the caller's Visual Studio or .NET toolchain.
The MCP service does not compile C# source, execute `.csproj`, `.props` or
`.targets` files, run MSBuild, run `dotnet build`, or run a build script. Send
the service a completed ZIP, never an arbitrary local path.

Use this SDK-style class-library template for a new SereinFlow library. Keep
the package-version setting as shown; add the library's own dependencies in
the second `ItemGroup`.

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <ManagePackageVersionsCentrally>false</ManagePackageVersionsCentrally>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="SereinFlow.Library" Version="*" />
    <!-- Add project dependencies. -->
  </ItemGroup>

  <PropertyGroup>
    <AssemblyName>SereinFlow.OpenCvLibrary</AssemblyName>
    <RootNamespace>SereinFlow.OpenCvLibrary</RootNamespace>
    <Version>1.0.0</Version>
    <EnableDynamicLoading>true</EnableDynamicLoading>
    <CopyLocalLockFileAssemblies>true</CopyLocalLockFileAssemblies>
  </PropertyGroup>

  <!-- Compile and create the ZIP. -->
  <!-- dotnet build -c Release -->
  <!-- or specify a runtime: dotnet build -c Release -r win-x64 -->
  <Target Name="CreatePackage" AfterTargets="Build">
    <RemoveDir Directories="$(IntermediateOutputPath)package" />
    <MakeDir Directories="$(IntermediateOutputPath)package\$(AssemblyName)-$(Version)" />
    <ItemGroup>
      <BuildFiles Include="$(TargetDir)**\*" Exclude="$(TargetDir)publish\**\*;$(TargetDir)win-x64\**\*;$(TargetDir)win-x86\**\*;$(TargetDir)linux-x64\**\*;$(TargetDir)linux-arm64\**\*;$(TargetDir)osx-x64\**\*;$(TargetDir)osx-arm64\**\*" />
    </ItemGroup>
    <Copy
      SourceFiles="@(BuildFiles)"
      DestinationFiles="@(BuildFiles->'$(IntermediateOutputPath)package\$(AssemblyName)-$(Version)\%(RecursiveDir)%(Filename)%(Extension)')" />
    <ZipDirectory
      SourceDirectory="$(IntermediateOutputPath)package"
      DestinationFile="$(MSBuildProjectDirectory)\$(AssemblyName)-$(Version).zip"
      Overwrite="true" />
    <RemoveDir Directories="$(IntermediateOutputPath)package" />
    <Message Text="Package generated: $(MSBuildProjectDirectory)\$(AssemblyName)-$(Version).zip" Importance="high" />
  </Target>

</Project>
```

Run one of these commands from the project directory or repository root:

```powershell
dotnet build path\to\Library.csproj -c Release
dotnet build path\to\Library.csproj -c Release -r win-x64
```

The ZIP is generated by the project's `CreatePackage` target after `Build`,
not after `Publish` and not by `dotnet pack`. The target copies the build
output from `$(TargetDir)`, excludes `$(TargetDir)publish` and stale nested
RID output directories, and removes its temporary staging directory after
creating the archive.

Let MSBuild evaluate `AssemblyName`, `Version`, `TargetPath`, `TargetDir`,
`TargetFramework` and `EnableDynamicLoading`; the latter must be `true`. The
ZIP validation rules are defined by the `zip` skill.

Report the absolute project path, build output directory, ZIP path, file count,
size and SHA-256 before previewing it.
