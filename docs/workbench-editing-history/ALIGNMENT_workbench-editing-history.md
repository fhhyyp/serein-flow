# Web 工作台编辑历史与本地工作副本需求对齐

> 阶段：Align 完成。日期：2026-08-22。
>
> 用户已授权自动执行；本文作为本轮实现依据。

## 原始需求与延续目标

用户要求继续完善功能。上一轮已完成多画布、节点拖拽、双语义连线和中英文切换；当前应用已展示撤销、重做、保存以及画布操作文案，但这些编辑路径尚未形成完整行为。

## 项目理解

- `CanvasState` 已按 `main`、`init`、`loading` 隔离节点和边，Domain 的 `CanvasLifecycle` 还包含 `Exit`。
- 当前保存按钮仅显示提示，刷新页面会丢失本地工作副本；撤销/重做按钮没有历史状态。
- 工作台尚未接入 T8 REST/OpenAPI，因此本轮不能声称已实现服务端保存、并发冲突或多设备同步。
- UI/UX PRO MAX 的 Vue 建议要求保持语义化按钮和动态 ARIA 状态；现有浅色 Minimalism & Swiss Style 是项目已确认的视觉基线，不能因其默认 OLED 推荐而变更。

## 本轮边界

包括：

- 对图结构和节点属性变更提供最多 50 步的撤销/重做。
- 支持为缺失的 `Init`、`Loading`、`Exit` 生命周期新增画布，且禁止删除主流程画布。
- 实现 `Ctrl/Cmd+S`、`Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` 与 `Ctrl/Cmd+Y`；在文本输入控件中不劫持撤销。
- 用版本化浏览器 `localStorage` 保存当前工作副本、活动画布和下一个节点序号，并在有效快照存在时恢复。
- 提供明确的未保存/已本地保存状态，动态禁用不可用的撤销、重做和画布删除命令。

不包括：

- REST/OpenAPI、SQLite 保存、乐观并发、跨设备同步、项目选择器和 API 错误恢复。
- 复制粘贴、框选、自动布局、流程校验、运行监控和脚本编辑。
- 旧 WPF Workbench、`.dnf`、旧脚本或离线客户端兼容。

## 风险与假设

| 风险 | 处理 |
| --- | --- |
| 历史记录错误收集选中状态 | 只在节点/边/画布/参数实际变更前记录，不把选中、语言和面板开关作为编辑命令。 |
| 大量拖拽事件导致历史膨胀 | 每次拖拽手势只记录一次初始快照，历史上限为 50。 |
| 过期或损坏的浏览器快照 | 使用显式格式版本和最小结构校验；不合法时回退示例画布。 |
| 浏览器保存被误当成服务器保存 | 状态文案明确写为“本地保存”；T8 后由 REST 保存状态替换。 |

## 待确认问题

无阻断问题。生命周期画布采用现有 Domain 枚举，避免新增未定义的自由画布类别。
