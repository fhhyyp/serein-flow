# 流程版本管理开发计划

## 目标

为每个流程提供开发版本与生产版本两条历史轨道。开发版本是编辑器默认工作版本；生产版本只能由开发版本显式发布产生，环境接口只执行当前生产版本。版本回滚不修改历史记录，而是从指定历史版本复制内容并创建新的递增版本。

## 已确认规则

1. 每个流程使用单一、严格递增的版本号，开发与生产不各自从 `v1` 重复计数。
2. 初始流程为开发 `v1`，没有生产版本。
3. 编辑器保存和类库升级创建开发版本。
4. 发布从当前开发头复制定义，创建新的生产版本并移动生产头。
5. 开发回滚只能选择开发历史；生产回滚只能选择生产历史。
6. 回滚始终创建新版本，备注自动生成：`由开发版本 vN 回滚` 或 `由生产版本 vN 回滚`。
7. 环境接口自动跟随当前生产头。发布和生产回滚影响后续接口调用，不影响已创建的运行快照。
8. 生产历史引用的类库工件必须保持项目引用，保证生产历史始终可回滚。

## 数据模型

`FlowDefinitionVersions` 保留不可变 JSON 快照和 `(FlowId, Version)` 主键，增加：

| 字段 | 用途 |
| --- | --- |
| `Track` | `Development` 或 `Production` |
| `Operation` | `Created`、`Saved`、`Published`、`RolledBack`、`LibraryUpgraded`、`Imported` |
| `ParentVersion` | 当前轨道此前的头版本 |
| `SourceVersion` | 本次内容的复制来源版本 |
| `Remark` | 发布或回滚备注 |
| `CreatedAt` | 版本创建时间；迁移历史允许未知 |

新增：

- `FlowProductionHeads`：每个流程的当前生产版本指针。
- `FlowVersionCounters`：每个流程的下一个全局递增版本号。

`FlowDefinitions` 继续表示当前开发头，编辑器保存时更新它。生产发布和生产回滚不覆盖 `FlowDefinitions`。

## 事务与并发

所有保存、发布、回滚和类库升级在一个 Unit of Work 中执行：验证当前头、原子分配版本、插入历史快照/类库绑定、更新开发头或生产头。请求携带对应头版本的乐观并发值；冲突时返回最新头版本且不产生新记录。

## API

- `GET /api/projects/{projectId}/flows/{flowId}/versions?track=development|production`
- `GET /api/projects/{projectId}/flows/{flowId}/versions/{version}`
- `POST /api/projects/{projectId}/flows/{flowId}/publish`
- `POST /api/projects/{projectId}/flows/{flowId}/versions/{version}/rollback`

项目目录摘要增加当前开发版本和可选当前生产版本。环境接口创建和公开调用均验证流程已有当前生产头；公开调用解析该生产快照，而不是读取开发头。

## 迁移

新增 SQLite migration `17`：

1. 为历史表增加版本元数据字段。
2. 创建生产头和版本计数器表。
3. 既有流程历史回填为开发 `Imported` 版本；不伪造历史操作时间。
4. 版本计数器从每个流程已有最大版本号加一开始。
5. 不自动将既有开发定义发布为生产版本。
6. 既有环境接口进入“等待生产版本”状态，直到流程显式发布。

## 类库约束

- 发布/回滚前使用现有类库校验逻辑验证目标定义。
- 任一生产历史版本引用的工件阻止取消项目引用。
- 开发历史回滚若引用已不可用工件，返回结构化诊断而不生成版本。
- 类库升级只产生开发轨道版本，并通过统一版本计数器分配版本号。

## 前端

- 命令栏展示 `开发 vN` 和可选 `生产 vM`，提供历史和发布命令。
- 历史对话框使用开发/生产分段标签，展示版本号、操作、来源、备注、时间、当前标记、预览和回滚。
- 未保存的编辑状态下禁用发布和回滚，避免覆盖本地工作区。
- 环境接口表单仅列出已有生产版本的流程，接口表显示当前生产版本。
- 版本操作成功后刷新项目目录和相关工作区状态；开发回滚重新加载画布并清空本地撤销栈。

## 验收与测试

1. 保存、发布、两类回滚均创建新的严格递增版本。
2. 开发/生产历史严格隔离，回滚不得跨轨道。
3. 自动备注和来源版本正确；历史 JSON 不被修改。
4. 环境接口无法绑定或调用无生产版本流程；后续开发保存不影响接口执行版本。
5. 生产回滚后，新接口调用使用新的生产头；已运行任务保持原快照。
6. 并发发布、保存、回滚和类库升级不会产生重复版本或半事务状态。
7. 生产历史引用的类库不能被取消项目引用。
8. SQLite 迁移、Application、API integration、前端单测和生产构建全部通过。
