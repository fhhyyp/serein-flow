# SereinFlow 数学类库与复杂分支流程任务风险报告

**日期：** 2026-08-30  
**范围：** SereinFlow 引擎、已连接的 MCP 服务、`sereinflow-ai-toolkit` Skill，以及本次“数学分析与决策演示”任务实际走过的类库打包、导入、类库附加、流程预览和流程应用路径。  
**结论：** 本次任务没有发现已经持久化的流程拓扑不一致，也没有发现未经确认的服务端写入；最终开发版本 `2` 的版本号、校验和、12 个节点和 32 条连接均已由服务端复读确认。主要风险集中在**作者端契约漂移、预览可审计性不足、类库包装规则矛盾，以及缺少开发态端到端执行验证能力**。这些问题会显著降低 AI/自动化流程编排的可靠性，且可能使“已通过预览”的流程在首次运行时才暴露问题。

## 1. 证据与边界

### 已观察到的事实

1. 项目、类库导入、项目类库附加和流程补丁均遵循了“预览 -> 人工 `APPLY` -> 应用 -> 复读”的顺序。
2. `sereinflow_preview_flow_patch` 的前两次请求均返回 MCP `-32602`：

   ```text
   The flow patch is invalid: The JSON value could not be converted to
   SereinFlow.Contracts.NodeDto. Path: $.type
   ```

   请求分别使用了读取模型显示的 PascalCase 枚举和小驼峰枚举。改为数值枚举后，同一候选拓扑通过预览，`validation.isValid=true`，诊断为空。
3. 成功预览的结构化差异将每个新增节点标记为 `isSensitive=true`，而完整候选定义约 21,814 tokens，超过单次工具输出可完整呈现的范围。
4. 类库初始 ZIP 包含 SDK 运行时依赖和 `.deps.json` / `.runtimeconfig.json` 时被连接服务拒绝。删除 `SereinFlow.Library.dll`、`.deps.json` 和 `.runtimeconfig.json` 后，只含主 DLL 与 PDB 的 ZIP 才通过服务端预览。
5. 重新读取项目时，项目摘要只返回流程概要；已附加类库只能从 `sereinflow_get_flow_edit_model` 的 `libraries` 字段确认。附加操作后项目的 `version` 和 `updatedAt` 仍与创建时相同。
6. 成功应用的响应会脱敏字面量参数：参数来源保留为 Literal，但 `valueJson` 和 `ui.literalValue` 返回 `null`。这符合 Skill 中“应用响应可能脱敏字面量”的约束。
7. 本次 MCP 工具目录提供流程预览、应用、拓扑和编辑模型读取，也提供既有调试状态读取；未提供创建开发态运行、启动调试会话或运行演示流程的工具。因此，本次只完成了静态校验和持久化复读，没有验证 DLL 调用、分支选择或 Flipflop 异步执行。
8. 当前 Skill 清单存在同一插件的重复 SereinFlow 入口；交接信息中引用的插件缓存路径在本次会话已失效，需重新定位另一缓存版本才能读取实际生效的 `SKILL.md`。

### 未验证的边界

- 没有发布生产版本，也没有执行生产运行。
- 没有用不同输入分别触发样本规模和风险评估的 Success、Failure、Error 路径。
- 没有依据本地源码推断或断言远端服务的内部实现。下文涉及远端行为的结论均以 MCP 返回和读模型为证；需要服务端日志才能确认根因的事项会明确标注。

## 3. 详细风险

### R-01：流程补丁枚举格式漂移

**证据：** 读取模型展示节点类型为 `Action`、`Flipflop`，而两种字符串枚举编码都被 `sereinflow_preview_flow_patch` 拒绝；使用数值编码后才通过。

**风险：**

- Agent 根据读模型或 Skill 生成的补丁会在预览阶段失败，形成无意义的重试循环。
- 枚举数值可读性差，未来新增、保留或删除枚举值时更容易产生版本兼容事故。
- 若某个客户端默认把未知数值反序列化为零值，可能将无效节点误解释为 `Action`。

**建议：**

1. 将 MCP 工具 schema、请求反序列化器和读取模型统一到一种稳定的字符串编码，建议小驼峰，例如 `action`、`flipflop`、`execution`、`previousNode`。
2. 在响应中返回 `schemaVersion`、`enumEncoding` 和可复制的最小合法补丁示例。
3. 在 MCP 层对字符串和数值提供显式兼容期；拒绝时返回稳定代码，例如 `mcp.flow_patch.enum_encoding_invalid`，并给出字段、期望值和当前协议版本。

### R-02：缺少强类型补丁与类库节点模板

**证据：** MCP Tool 元数据将 `operations` 表示为 `Array<unknown>`。附加类库后的编辑模型提供节点契约、参数 ID 和类型，但不提供“添加此类库节点”的完整节点模板。作者必须自行拼接节点类型、端口、参数 UI 元数据、运行时库信息和连接对象。

**风险：**

- 使用者容易遗漏运行时字段，或错误填入 `className`、`methodName`、DLL 版本、参数 CLR 名称和端口。
- 扫描契约中的参数 `id`、显示 `name` 和 CLR 参数名可以不同；错误映射会在首次 DLL 调用时表现为方法匹配、参数绑定或类型转换失败。
- Tool/Skill 更新后，手工复制的 Node DTO 可能静默失效。

**建议：**

1. 提供 `sereinflow_create_library_node_template`，输入 `projectId`、`libraryId`、`libraryNodeContractId` 和位置，返回完全规范化的 Node DTO。
2. 将 `preview_flow_patch.operations` 声明为严格 JSON Schema，而不是无类型数组，并在 Tool 描述中附带 discriminated-union 示例。
3. 提供 `sereinflow_preview_flow_patch_normalized` 或在预览响应中返回规范化操作，便于客户端回写而不是猜测字段。

### R-03：数据端口 ID 与数据连线目标 ID 不一致

**证据：** 编辑模型中节点端口采用 `param-<参数ID>` 形式，例如 `param-统计结果`；成功的 Data Connection 的 `toPortId` 却必须使用裸参数 ID `统计结果`。这两种表示同属“端口 ID”，但语义不同。

**风险：**

- UI 拖拽、API 客户端和 Agent 若直接使用端口列表中的 ID 建立连线，会被拒绝或写出不可执行连接。
- 同一个数据目标存在两个候选标识，会导致生成器、比较器与迁移器无法稳定地做结构化 diff。

**建议：**

1. 统一数据连线 `toPortId` 与暴露端口 ID；推荐直接使用 `param-<参数ID>`。
2. 若必须保留兼容性，在读取模型中增加 `connectionTargetId` 或 `bindingParameterId`，不要复用 `toPortId` 表示两种概念。
3. 在预览诊断中检测 `param-`/裸 ID 混用并返回确定性的修正建议。

### R-04：类库包装规范与导入器实际约束冲突

**证据：** Skill 明确要求 ZIP 包含“完整 `dotnet publish` 运行时闭包”；本次导入却依次拒绝 `SereinFlow.Library.dll`、`.deps.json` 和 `.runtimeconfig.json`，最终只接受主 DLL 与 PDB。

**风险：**

- 按文档打包的制品无法导入，发布流水线不可重复。
- 若实际运行时又需要被拒绝的依赖，当前扫描通过的最小包会在 Worker 首次加载时失败。
- Agent 会用“删文件直至通过”的试探策略，可能误删真正需要的第三方或原生依赖。

**建议：**

1. 把“宿主提供的共享程序集”“明确禁止文件”“必须随包携带的托管/原生依赖”写成版本化 allowlist/denylist，并由 `preview_library_package` 返回机器可读的每文件判定原因。
2. 区分 scan-safe 包、upload-accepted 包和 runtime-loadable 包；导入预览应明确每一种状态。
3. 在类库 Skill 中以可执行的发布清单替代泛化的“完整闭包”描述，并提供 ZIP 自检命令或脚本。

### R-05：预览差异无法支撑充分的人工审批

**证据：** 成功预览中每个新增节点的 `after` 内容均被标为敏感；完整候选定义超过工具输出上限。虽然预览给出了 `isValid=true` 和候选校验和，但审批者无法仅依赖服务器 diff 逐项审阅所有节点、参数与连线。

**风险：**

- “预览 -> APPLY”可能退化为只批准摘要，而不是批准真实变更。
- 非敏感元数据（节点类型、连接方向、库版本）与字面量机密一起被整体隐藏，降低变更可解释性。
- 长流程对话输出截断后，Agent 和用户都无法可靠确认差异是否完整。

**建议：**

1. 把敏感性下沉到字面量值、脚本内容和明确机密字段，节点 ID、端口、连接、库哈希和参数类型保持可见。
2. 提供分页或摘要资源，例如 `sereinflow://mcp-previews/{id}/diff?cursor=...`，并返回 `totalChanges`、`hasMore` 和按 kind 的计数。
3. 增加不可绕过的审批摘要：入口变化、节点/连接增删统计、类库和版本变化、敏感字段数量、候选 checksum。

### R-06：缺少开发态运行或调试启动能力

**证据：** 本次暴露的 MCP 工具仅能读取已有运行/调试状态，不能创建开发态运行或启动调试会话。流程最终能通过静态预览并保存，但无法通过 MCP 验证本地 DLL 加载、`IFlowContext.SelectFailure/SelectError` 路由、数据转换和 `Task<string>` Flipflop 行为。

**风险：**

- 类库扫描成功不等于 Worker 可加载、依赖可解析或方法可调用。
- 高分支流程可能在第一次生产执行才发现错误路径未配置、分支无法收敛或异步节点行为不符合预期。
- “演示流程”缺乏可重复的验收证据，用户只能看到拓扑而不能看到实际三路结果。

**建议：**

1. 提供开发轨道专用的 `sereinflow_start_debug_run` 或 `sereinflow_run_flow`，要求显式开发版本、超时、步数上限、项目输入，并绝不隐式发布。
2. 允许以受限预设输入运行三次，分别覆盖 Success、Failure、Error；返回分支、节点输入输出和执行时间的摘要。
3. 对 uploaded DLL 增加独立的 Worker 预热/加载检查，区分“PE 扫描成功”和“运行时可加载”。

### R-07：配置脱敏没有可验证摘要

**证据：** 应用响应将全部字面量显示为 `null`。这是安全取舍，但在没有字段级“已配置”标记、值哈希、计数或安全读取授权时，复读无法证明预览中的示例输入仍然存在。

**风险：** 配置可能被意外规范化、丢失或替换，而审批与应用后的检查无法区分“值被安全隐藏”和“值确实为空”。

**建议：** 对每个参数返回 `isConfigured`、`valueType`、`valueDigest` 和 `isRedacted`；在获得显式读取授权时才返回字面量本身。候选预览与应用后版本应能比较该摘要。

### R-08：项目级类库引用缺少可审计投影

**证据：** 类库附加成功后，项目读取仍显示创建时的 `version=1` 和相同 `updatedAt`；项目摘要中没有 `libraryReferences`。只有流程编辑模型能间接显示可用类库。

**风险：** 项目级授权面和流程使用的类库集合无法从项目主资源审计；缓存和同步系统可能错误判断项目未变化。

**建议：** 在项目读模型中返回不可变的 `libraryReferences`（库 ID、版本、SHA-256、附加时间）；对附加/解除附加明确项目修订策略，并记录单独的引用版本或审计序号。

### R-09：执行收敛语义未被声明

**证据：** 本次有效候选将样本规模节点的 Success、Failure、Error 三条执行边全部指向同一“计算二次方程根”节点。预览接受了该图，但 MCP 契约没有说明多入边情况下是每次触发、等待全部上游、去重还是使用令牌关联。

**风险：** 在 `Parallel` 策略下，更复杂的图可能让同一节点被重复调用，或者出现与用户预期不一致的 join 行为。当前任务只会由单一分支选择一个后继，因此尚未观察到错误执行。

**建议：** 在节点/端口契约中声明执行输入基数与合并策略；预览应对多入边产生信息性诊断，并提供显式 Join/Fork 节点或 token/join 策略。

### R-10：Skill 缓存与操作命名漂移

**证据：** 会话技能目录显示重复 SereinFlow 入口，且交接时记录的缓存版本路径已不存在；本次需重新枚举缓存目录。Skill 文本列举流程操作为 `add_node` 等下划线名称，而成功 MCP 请求使用 `addNode` 等小驼峰名称。

**风险：** Agent 可能加载旧 Skill、选择错误副本，或将文档中的操作名直接用于 MCP；错误通常只会在预览时才暴露。

**建议：**

1. Skill manifest 增加唯一 `skillId`、语义版本、兼容的 MCP schema 版本和弃用信息；宿主只暴露一个当前入口。
2. 在 Tool 描述中直接生成操作 union，而不是由 Skill 手写一份可能失效的名称表。
3. 启动时校验 Skill 版本与服务器 `schemaVersion`，不兼容时给出可操作的升级提示。

## 4. 优先整改顺序

### 立即处理（P1）

1. 统一 `preview_flow_patch` 的枚举编码与强类型 schema，并新增类库节点模板 API。
2. 修订类库 ZIP 规范，令预览结果对每个被接受/拒绝文件提供稳定原因；增加 runtime-loadability 检查。
3. 改造 preview diff 脱敏与分页，使人工 `APPLY` 能审阅非敏感拓扑。
4. 提供开发态受限运行/调试启动与三分支验收，保持生产轨道不受影响。

### 随后处理（P2）

1. 统一数据端口和参数绑定 ID，并提供旧格式迁移。
2. 向项目读模型加入类库引用与审计修订信息。
3. 为脱敏配置返回 presence/digest 摘要。
4. 明确多入边执行语义、并发行为和 join 模型。
5. 合并重复 Skill 入口，建立 Skill/MCP schema 兼容检查。

## 5. 建议验收矩阵

| 场景 | 期望结果 |
| --- | --- |
| 字符串枚举与数值枚举补丁 | 在兼容期都可接收并规范化；之后仅接受文档规定格式且错误带稳定代码。 |
| 从 library contract 创建节点 | 单一模板 Tool 返回可保存节点，无需客户端拼接运行时元数据。 |
| 数据端口连线 | 端口列表 ID 与 `toPortId` 完全一致；UI 和 MCP 使用同一标识。 |
| 标准 publish ZIP | 文档生成的 ZIP 直接通过 preview；被拒绝文件逐个显示规则。 |
| 非敏感流程预览 | 可分页浏览全部节点、连接和类库版本；仅机密字面量被掩盖。 |
| 开发态三分支运行 | 输入分别触发 Success、Failure、Error，返回确定的路径和节点输出摘要。 |
| 应用后复读 | 节点、连接、库引用、入口、配置 digest 与候选预览一致。 |
| Skill 升级 | 仅有一个当前入口，Skill 与 MCP schema 不匹配时启动即失败并说明升级路径。 |

## 6. 任务状态与后续建议

本次已构建并导入 `SereinFlow.MathLibrary` `1.0.0`，并将数学演示流程应用为开发版本 `2`。服务端复读确认：入口为 `math-sample-gate`，主画布有 12 个节点、32 条连接，类库引用可用，校验和为：

```text
37e3e91c189d3fe41df01666dfed0daf93fe9d165723e08a95d634b50ca9d016
```

在 R-06 的开发态执行能力补齐前，不建议将此类自动生成的类库流程直接作为生产验收样例发布。最低限度应先在受限 Worker 中运行三组输入，保存每个分支的节点输出与库加载诊断，再进入生产发布预览。
