# 先看全貌

可以把 SereinFlow 想成一条从“设计”走到“执行”的路线：

```text
项目 → 流程 → 节点和连接 → 保存的版本 → 一次运行 → 结果
```

| 名称 | 用一句话理解 |
| --- | --- |
| 项目 | 放流程和相关类库的地方。 |
| 流程 | 你画出的执行步骤。 |
| 节点 | 流程里的一个具体动作。 |
| 版本 | 某次保存或发布时的流程内容。 |
| 运行 | 让流程真正执行一次。 |
| 公开接口 | 给外部程序一个稳定的调用入口。 |

## 推荐阅读顺序

1. [项目与流程](/modules/projects-and-flows)：理解画布保存在哪里。
2. [节点与类库](/modules/nodes-and-libraries)：理解流程能做哪些动作。
3. [版本与发布](/modules/versions)：理解编辑中的流程和对外使用的流程。
4. [运行与结果](/modules/runs)：理解每次执行会留下什么。
5. [调试流程](/modules/debugging)：一步一步找出流程哪里出了问题。
6. [公开流程接口](/modules/public-interfaces)：把已发布的流程交给外部程序调用。
7. [环境设置与密钥](/modules/environment)：控制服务容量和访问权限。

每篇文章都先解释用途，再给出会用到的当前接口。需要逐个字段查阅时，进入 [API 手册](/api/)。
