# 版本与发布

保存流程像保存草稿；**发布**则是告诉系统：“外部程序现在可以按这一版来调用。”这两件事分开，便于你继续修改，而不立刻影响已经发布的流程。

## 开发版本与生产版本

- **开发版本**：编辑和保存时产生，适合继续调整。
- **生产版本**：发布后给公开流程接口使用。

创建公开流程接口之前，目标流程必须先有生产版本。否则服务器会返回 `409`，提示需要发布。

## 为什么修改时要带版本号

多人或多个程序同时编辑同一条流程时，后保存的人可能会覆盖前一个人的修改。SereinFlow 要求保存时带上你刚才看到的版本号 `expectedVersion`。如果当前版本已变，保存返回 `409`，你应重新读取、检查差异，再提交。

发布时也要带上 `expectedDevelopmentVersion`。系统会检查流程能否执行，再产生新的生产版本。

## 回滚是什么

回滚不是删除历史记录，而是用一个旧版本的内容生成新的当前版本。它同样需要你提供当前轨道的期望版本，避免在别人刚发布时误操作。

接口与请求字段见[流程版本 API](/api/versions)。
